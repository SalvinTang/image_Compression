## 🐛 解决的关键问题

### 1. 快速操作显示位置问题 ✅
**问题**: 服务直接显示在右键菜单顶层，而不是"快速操作"子菜单中

**原因**: `document.wflow` 中的 `inputTypeIdentifier` 设置错误
- ❌ 错误: `public.image`
- ✅ 正确: `com.apple.Automator.fileSystemObject.image`

**解决**: 修改为正确的 Automator 文件系统对象类型标识符

### 2. Shell 脚本执行错误 ✅
**问题**: 点击快速操作后提示"Shell 脚本错误"

**原因**: Automator 执行脚本时，`$0` 返回 `-`，导致 `dirname "$0"` 无法获取正确路径

**解决**: 使用固定路径而非相对路径
```bash
# 错误方式
WORKFLOW_DIR="$(dirname "$0")"
EXECUTABLE="$WORKFLOW_DIR/../Resources/ImageResizeDialog"

# 正确方式
if [ -f "$HOME/Library/Services/图片压缩.workflow/Contents/Resources/ImageResizeDialog" ]; then
    EXECUTABLE="$HOME/Library/Services/图片压缩.workflow/Contents/Resources/ImageResizeDialog"
elif [ -f "/Library/Services/图片压缩.workflow/Contents/Resources/ImageResizeDialog" ]; then
    EXECUTABLE="/Library/Services/图片压缩.workflow/Contents/Resources/ImageResizeDialog"
fi
```

### 3. NSServices 配置问题 ✅
**问题**: 删除 `NSServices` 后服务无法识别

**解决**: 保留 `NSServices` 配置，但确保 `document.wflow` 的 `inputTypeIdentifier` 正确

## 🎓 经验总结

### 关键发现

1. **Automator 输入类型标识符**
   - 必须使用 `com.apple.Automator.fileSystemObject.*` 格式
   - 不能使用 UTI（如 `public.image`）
   - 可以在"自动操作" App 中查看和修改

2. **Shell 脚本路径问题**
   - Automator 执行时 `$0` 不可靠
   - 应使用固定路径或环境变量
   - 需要同时支持用户级和系统级安装路径

3. **服务显示位置**
   - `NSServices` 配置不决定显示位置
   - `inputTypeIdentifier` 才是关键
   - 正确配置后会自动显示在"快速操作"子菜单

### 最佳实践

1. **架构设计**
   - 嵌入式架构优于独立应用
   - 系统级安装优于用户级安装
   - 自包含优于外部依赖

2. **开发流程**
   - 先在"自动操作" App 中测试配置
   - 使用调试脚本记录执行日志
   - 分步验证每个环节

3. **文档编写**
   - 记录所有遇到的问题和解决方案
   - 提供清晰的架构说明
   - 包含完整的使用指南
